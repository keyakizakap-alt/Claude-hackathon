## 一文で
**「合わなかった化粧品」の記録から、共通して含まれる成分の候補を見つけ、次に買う化粧品を購入前にチェックできるWebアプリ。**

## ターゲット
- 主：肌荒れしやすい・敏感肌を自覚する20〜40代（過去に化粧品で肌の調子が悪くなった経験がある人）
- 副：成分を見て化粧品を選ぶ人

## 中心となる体験（MVP）
1. **商品を登録**：パッケージ裏の全成分表示を撮影、またはテキストを貼り付け → AIが成分名を読み取り、表記ゆれをそろえて一覧化（利用者が確認・修正できる）
2. **反応を記録**：「問題なかった／少し合わなかった／合わなかった」と症状のメモ
3. **共通成分の候補を表示**：合わなかった商品に多く含まれ、問題なかった商品には少ない成分を、**コードによる統計処理**で順位付け。根拠（どの商品に含まれていたか）を必ず表示
4. **購入前チェック**：気になる商品の全成分を読み込むと、自分の「注意したい成分」との一致、組み合わせ注意（例：レチノールとAHAの同時使用）を表示
5. **皮膚科向けの記録出力**：使用した商品・成分・反応の一覧を印刷・PDF化

## AIの役割（使う範囲を限定）
| 処理 | 担当 |
|---|---|
| 全成分表示の画像・テキストから成分名を抽出・正規化 | LLM（画像認識） |
| 成分辞書との照合 | コード＋データベース |
| 共通成分のスコア計算 | コード（決定論的） |
| 結果のやさしい説明文 | LLM（根拠データの範囲内に限定） |
| 医学的な判断 | **行わない**（皮膚科の受診を案内） |

## 価値提案
- 「他人の口コミ」ではなく「**自分の肌の記録**」に基づく
- 判定の根拠がすべて見える（ブラックボックスにしない）
- 肌の写真は扱わない（パッケージの文字だけ）

## 主なリスク
1. 消費者の支払意思が低い → 無料で価値を出し、継続率を先に検証
2. 読み取り精度 → 手動修正の画面と評価データで品質を管理
3. 薬機法・医師法上の表現 → 「特定」「診断」「治る」などの言葉を使わない。専門家確認事項として明記
4. 成分辞書の整備 → 日本の表示名称を中心に、利用規約上問題のない公開情報から段階的に作成（出典を要確認）
